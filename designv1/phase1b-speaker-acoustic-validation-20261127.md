# 阶段一专项 B：S3 扬声器声学验证记录

日期：2026-11-27
结论：**BLOCKED，扬声器清晰语音验收未通过**。按照用户允许的停止条件，完成一次受控校准和一次同源语音复测后，停止重复声学试验。阶段一整体仍未通过；272 个越窗拒包的同类故障复现、恢复修补及 300 秒结果见[专项 A 记录](phase1a-jitter-window-validation-20261127.md)，不能改变本声学结论。

## 1. 本轮范围

实际路径：Android 诊断应用播放已知 PCM → 蓝牙 HFP/mSBC → 经典 ESP32 → 无线 UDP → S3 codec 前 → S3 扬声器 → 电脑 Realtek 麦克风录音。

- S3：COM3，音量经 HTTP 读回为 60%。
- 经典 ESP32：COM5；SCO 活动期间 Wi-Fi enabled/started/ready、network_mode 均为 true。
- Android：`TPE9X18C17W07990`，网关蓝牙地址 `58:2A:BD:D5:C5:EE`。
- 电脑输入：Realtek 麦克风阵列，sounddevice 设备 9，WASAPI，48 kHz 单声道。电脑扬声器未参与刺激输出。
- 同时采集网关 HFP 解码 PCM、S3 codec 前 PCM、电脑声学 WAV、两端带主机时间戳的串口日志、Android 路由与会话记录。
- 本轮没有修改或烧录固件，没有清除 NVS、Wi-Fi 或蓝牙配对。

这是非拨号 SCO 诊断，不能代替运营商来电、自动接听、双向清晰语音或五分钟压测验收。Android 路由 API 仍返回不可用，测试保留 `routing_api_verified=false`；活动 audio policy 和诊断应用 SCO 输入／输出线程得到验证，不能把此结果写成路由 API 通过。

## 2. 实施与结果

### 首轮已有语音录音复核

目录：`D:\work\Bluetooth-gateway\artifacts\android-speaker-acoustic-phase1b-20261127-01`。

| 观测点 | 录音时长 | 同模型参考 ASR 字符差异 |
| --- | --- | --- |
| 网关 HFP 解码 | 59.9025 s | 0/109（0%） |
| S3 codec 前 | 59.94 s | 0/109（0%） |
| 电脑声学拾音 | 62.36 s | 34/109（31.19%） |

声学文件原始 RMS 约 81.8，峰值 2593，未发生 PCM 满幅削波。ASR 输入经过明确记录的离线归一化，仍有漏词与错词。归一化不构成信噪比改善或声学验收。

必须更正的早期判读：

1. 参考字数是 109，早期写出的 116 和 29.3% 错误，以各份 `result.json` 的 `reference_characters` 和 `character_error_rate` 为准。
2. Android 实际事件是 `wav_then_silence`；本轮没有播放 750 Hz 校准音。“750 Hz 目标窗口为零”不适用。
3. 已知语料只有 37.185 秒，之后是源端静音。整段 60 秒的低能量窗口不能直接算作丢字或链路断音。
4. 随后单独录制的噪声基线不在同一会话，输入电平也未固定，不能据此将约 6.3 dB 写成正式 SNR。
5. 两次 `decoded_frames` 停滞发生在语料结束后的静音尾段。原报告 FAIL 保留；计数真实停滞不等于已经证明活动语音被截断。

使用 `tools/compare_speech.py` 排除源静音后，声学包络相关性约 0.774、源活动覆盖 18.04 秒，无未覆盖活动区；相对增益下降超过 14 dB 的候选片段最长 60 ms。该对照仍受噪声掩盖缺音影响，不能用“未检出 20 dB 候选断音”替代清晰度验收。

### 受控校准

目录：`D:\work\Bluetooth-gateway\artifacts\android-speaker-acoustic-phase1b-20261127-calibration-02`。

电脑输入端点从原系统音量标量 `0.8667865` 临时设为 `1.0`，解除静音；先保存同设置的 3 秒噪声 WAV，再运行 15 秒 SCO。刺激为 0–2 秒静音、2–10 秒 750 Hz 音段、10–15 秒静音，幅度 2600；两端数字 PCM 同时保存。系统音量标量不是声压或物理增益标定。

网关和 S3 数字录音均保留该音段。声学文件约 17.25 秒、RMS 196.9、峰值 18138、削波比例 0。按 100 ms Hann 窗、750 Hz ±30 Hz 频带分析，对整段只拟合一个时间偏移，再排除音段边界各 500 ms：

- 声学目标音开关包络相关性约 0.813。
- 目标频带开／关中位功率约为 10707/1307；扣除关断噪声后的频带 SNR 描述值约 8.57 dB。
- 音段内目标频带占 300–3400 Hz 总功率的中位比例约 31.4%，明显混有非目标声音。

这些结果支持录音中存在与刺激相关的频率成分，不能证明语音清晰。此 SNR 是所述窗口与频带的描述值，设备处理和噪声变化仍有影响，不是经校准的硬件指标。权威数值见 `tone-review-v2.json`，其明确替代初版 `tone-review.json`；数字静音噪声为零时 SNR 记为 null，不报告虚假的超高数值。

本轮原始报告为 `MEDIA_RUN_COMPLETE`，没有传输存活检查错误；这不是音质 PASS。共同活动状态窗口约 41.095 秒，mSBC 原始坏帧 507/5479（9.25%）、raw_drop=6；上行 UDP 接受增量 2054，活动采样窗口内 late/window/socket error 增量均为 0。S3 活动窗口最后快照 gaps/PLC=3、rebuffer=0、max_gap_ms=107；最后快照后还有未被该窗口覆盖的尾部，不能把快照当作全会话最终计数。

## 4. 停止原因与后续条件

已确认已知中文内容可以完整识别到 S3 codec 前；电脑录到与参考相关的声学输出，但无法可靠识别完整语句。尚不能区分：

- S3 codec 后的放大器、扬声器或播放电平问题；
- 扬声器与麦克风的距离、方向、遮挡及环境噪声；
- Realtek 麦克风阵列的处理、增益及自身拾音表现。

本轮无法独立标定或调整这些物理条件。继续重复同一摆位、同一端点的语音测试不能消除上述歧义，因此按用户允许的条件停止。结论是**声学验收 BLOCKED**，不能写成扬声器损坏，也不能写成声学语音通过。

恢复该项验证需要一个实际改变的测量条件：麦克风靠近 S3 并固定距离，或换独立录音设备／手机物理麦克风。手机方案必须确认捕获内置麦克风，防止录到 HFP 回传或数字环回。保留静音对照、已知频率、同源中文和数字录音，再分别判定清晰度与连续性；验收阈值不能为使既有结果通过而临时放宽。

测试后已读回：两端 `ready/remote_fresh=true`，经典 `audio=0/call_active=false`，Wi-Fi 与 network_mode 保持开启，诊断缓存释放；S3 音量仍为 60%。电脑麦克风恢复原标量／静音状态，手机两路临时音量恢复，串口均已关闭。复核报告和最终状态在复测目录中，`acceptance-review.json` 绑定相关文件哈希。原始录音、账号文件和构建产物不纳入提交。
