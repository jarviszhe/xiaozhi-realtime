# Android 按钮语音测试：无声原因、实现与验证

日期：2026-11-28。手机为 Huawei ATU-AL10 / Android 8，两板为 COM5 经典 ESP32 与 COM3 ESP32-S3。

## 结论与原先说明的更正

原 `dev.gateway.calltest` APK 仅通过 Telecom ConnectionService 创建本地电话状态，没有录制手机麦克风、向 SCO 写音频或从 SCO 收集回复。此前自动化语音依赖另外的 `dev.gateway.hfptest` 工具注入参考 WAV。因此，“创建本地来电后，直接对着手机说话就能传给 S3”的说明不成立，只有呼叫状态测试不能证明手机麦克风可用。

新版加入分步语音链路，并在该手机安装验证：①无通话时录音 → ②关闭本机录音，创建本地来电并通过真实 HFP/SCO 发送 → ③挂断、释放 SCO，从手机喇叭回放收到的回复。不拨真实电话、不使用 SIM 账户。**手机自身麦克风/喇叭与 SCO 同时工作的实时双向转发尚未验证成功。** 分步实现不能写成实时电话验收通过。

## 用户操作

1. 手机蓝牙连接 `ESP32-HFP-Gateway` 并启用通话音频。两板联网、绑定，S3 为 AI 接听模式并已配置云服务。
2. 打开 `Gateway Local Call Test`。本机账户已启用；首次安装可点“首次使用：启用本地电话账户”，在系统页面启用并允许所需权限。
3. 点击“① 录音”，对手机说一句话，最长 20 秒。此时只在手机录音，S3 尚无反应是预期。
4. 点击“② 说完了，发送给设备”，约 3 秒自动接听；随后有 4 秒静音预留给设备启动云会话。等待约 15–30 秒，设备完成回复后点“③ 结束测试并听设备回复”。
5. 回复从手机喇叭播放；可“重听”，可“取消录音 / 挂断 / 停止播放”。收集上限为 60 秒，到时自动挂断，再点击③回放。未收到可靠音频会明确显示错误。

AI 接听模式的来电音频交给云端，不能用 S3 本地扬声器是否立即出声判断来电输入成功。需要同时看转写、回复录音与两板日志。人工接管、本地 S3 麦克风/扬声器不属于本次 APK 验证路径。

## 验证过程与证据边界

早期四端点实时转发原型未通过，录音曾返回 0，设备路由 API 多次返回 null。随后发现旧 `dev.gateway.hfptest` 仍残留原生录音资源，普通 stop 未完全释放，强制停止旧应用后，本机录音才实际路由到内置麦克风。因此既不能宣称实时方案成功，也不能据此断言该手机永远不支持实时方案。

实际路由另存 Android audio_policy：本机录音为 `AUDIO_DEVICE_IN_BUILTIN_MIC`，SCO 会话使用蓝牙端点；回复回放时 `AUDIO_MODE_NORMAL`，活动媒体输出为手机扬声器。`setPreferredDevice` 成功及路由查询返回 null 均不单独作为路由成功证明。
